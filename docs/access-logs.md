# 访问日志

日志页顶部可按访问域名、客户端 IP、路径、用户名和认证结果筛选。时间支持最近 1／6／24 小时、7 天、全部保留记录和自定义范围。明细、统计、趋势图及聚合使用同一组条件；点击聚合分组可保留时间范围并查看对应明细。

时间表示请求开始时刻。自定义输入使用浏览器所在时区，格式为 `YYYY-MM-DD HH:mm`，起止边界均包含在内。界面日期和数字跟随当前中英文语言选择，接口使用带时区的 RFC3339 时间。筛选条件、分页和聚合选项保存在页面地址中，刷新或分享地址可以恢复。

日志仍最多保留 10,000 条，因此选择 7 天不保证包含这 7 天的全部请求。更早的记录可能已经被覆盖或按保留策略删除。新增的域名字段保存请求到达网关时的域名，历史日志没有该字段时显示“未记录”，不会根据当前路由猜测历史域名。

## 清理

管理员可在日志页点击“清理日志”，选择：

- **当前筛选结果**：清理满足全部筛选条件的日志，范围包含所有分页。
- **过期日志**：按设置页已保存的保留天数清理；保留天数为 0 时禁用自动／过期清理。
- **全部保留日志**：明确清理截止时间以内的全部请求日志。

弹窗先预览范围、当前匹配数量和截止时间，再由管理员确认删除。截止时间之后开始的请求不会被这次操作删除；已经开始但尚未结束的请求可能使最终数量变化。成功提示显示实际删除数。删除不可撤销，写盘失败不会报告成功。

设置页保留原有保留策略入口，其“立即清理”使用同一个预览和确认弹窗。未保存的保留天数草稿不会用于删除。

## 接口

`GET /api/access-logs`、`GET /api/access-logs/stats` 和 `GET /api/access-logs/aggregate` 支持相同的 `host`、`client_ip`、`path`、`username`、`auth_result`、`route_id`、`status_code`、`start_time`、`end_time` 条件。`duration=all` 表示全部保留时间；原有 duration 参数继续兼容，显式时间范围优先。聚合支持 `group_by=host`。

管理员清理接口为 `POST /api/access-logs/purge`。先提交 `preview: true`，再将返回的 `cutoff_time` 与相同模式、条件一起提交执行：

```json
{
  "mode": "filtered",
  "filters": { "host": "api.example.com", "end_time": "2026-09-09T00:00:00Z" },
  "preview": true
}
```

预览返回 `matched` 和 `cutoff_time`；执行时将 `preview` 改为 `false` 并加入该 `cutoff_time`，响应返回实际 `removed`。过期清理返回的截止时间是冻结的过期阈值，保留策略变化不会扩大已经预览的清理范围。兼容单端口模式时，接口前缀为 `/_authgate/api`。
